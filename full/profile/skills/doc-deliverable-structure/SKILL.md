# Document and Deliverable Structure

## Use when
Use when a task needs durable documentation and it is unclear whether one document should contain both the operating procedure and the deliverable's required form or content.

## Rule
Create separate documents when the procedure and the deliverable change independently:
- **Procedure document:** purpose, workflow, inputs, controls, validation, and maintenance.
- **Format or content document:** required sections, schema, tone, examples, acceptance criteria, and reusable template.

## Procedure
1. Identify the reader and the decision each document must support.
2. Split only when independent change would otherwise create confusion.
3. Keep identifiers, requirements, and assumptions explicit.
4. Verify capability claims against authoritative documentation before recording them.

## Output
Return the document map, ownership, update triggers, and concise outlines.

## Boundaries
Do not invent platform capabilities, embed personal paths, or preserve project-specific context in a global skill.
